# ADR-002: Vendor the drawing engine and type its boundaries

Status: Accepted; initial typing probe complete.
Date: 2026-11-05.

## Context

AnimatedDrawings is archived and its Python 3.8-era dependencies include
TorchServe and Flask. The package only needs its deformation and rendering
engine, with compatibility fixes and typed boundaries for strict pyright.

## Decision

I vendor only animated_drawings/ at commit
b859684857519c7424da51a0b0862fbd1fd258f4 into
copypaw/vendor/animated_drawings/. Retain the MIT header and record every
change in NOTICE and this ADR. Do not install the upstream dependency set.

I keep these compatibility changes:

- Replace pkg_resources.resource_filename in config.py, utils.py,
  view/window_view.py and view/mesa_view.py with importlib.resources.files rooted
  at copypaw.vendor.animated_drawings. setuptools no longer supplies the
  old resource interface.
- Replace model/bvh.py's mutable channels=[] default with None and allocate a
  fresh list so a second BVH load retains the same channel mask.
- Dump generated joint mappings as Python tuples with yaml.Dumper, preserving
  the !!python/tuple tags accepted by the engine's yaml.FullLoader.
- Keep scikit-learn for the module-level PCA import and tqdm for video rendering.
  Do not call the debug-only matplotlib plotting function or add matplotlib.
- Record NumPy 2 and Shapely 2 fixes individually when incompatibilities appear.

Ship shaders and mvc_base_cfg.yaml as wheel data. Add adjacent .pyi declarations
for every imported vendored engine or rtmlib name, exposing only the concrete
signatures used. List stubs in NOTICE. Use scipy-stubs and types-PyYAML for
third-party typing, and typings/ for remaining probed gaps. Do not suppress
strict errors or cast them away.

## Consequences

The project maintains the vendored fixes and licence notices. Engine rendering,
repeat BVH loads, tuple YAML and wheel contents need regression coverage.
The engine code is vendored. The historical typing evidence below establishes
static compatibility only; it does not establish runtime rendering behavior.

## Initial typing probe, 2026-11-05

A temporary `_typing_probe.py` called APIs from all eight required libraries:

- OpenCV: `VideoCapture`, `read`, `get`, `release`, `cvtColor`, `resize`,
  `threshold`, and `morphologyEx`.
- ONNX Runtime: `InferenceSession`, `get_inputs`, input `name`, `run`, and
  `get_available_providers`.
- SciPy: `signal.savgol_filter` and `signal.freqz`.
- scikit-image: `measure.label`, `morphology.binary_opening`, and `morphology.disk`.
- imageio v2: `mimsave` and `imread`.
- PyYAML: `dump` with `Dumper` and `load` with `FullLoader`, including tuple data.
- Typer: `Typer`, command registration, and `echo`.
- Rich: `Console.print` and `progress.track`.

The first `uv run pyright` reported 11 errors. ONNX Runtime had unknown input
metadata, inference arguments, output container elements, and provider discovery.
scikit-image had partially unknown signatures and a missing public export
declaration for `binary_opening`. imageio had unknown plugin keyword arguments.

I use `scipy-stubs` and `types-PyYAML` to cover SciPy and PyYAML.
OpenCV, Typer, and Rich required no additional declarations for these calls.

## Declaration fixes

`typings/onnxruntime/__init__.pyi` declares the probed session methods, input
metadata, provider discovery, and concrete recursive output values, retaining
arrays, sparse tensors, lists, and maps as distinct possibilities.

`typings/skimage/measure/__init__.pyi` declares `label`, including its optional
component count. `typings/skimage/morphology/__init__.pyi` declares
`binary_opening` and the default uint8, non-decomposed `disk` footprint.

`typings/imageio/v2.pyi` declares file-based `imread` and the probed multi-frame
`mimsave` call with `fps`. The reader retains an unspecified NumPy scalar dtype
because image formats can return data other than uint8.

These declarations cover the call forms probed, rather than every library API.
Expand them against the installed library's documented signature when another
call form is first used. They introduce no runtime code or suppression.

With those declarations present, `uv run pyright` reported:

```text
0 errors, 0 warnings, 0 informations
```

The probe was checked statically, not executed. No models or user media were
downloaded. The temporary module was deleted after this result was recorded.
