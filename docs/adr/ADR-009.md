# ADR-009: Keep user inputs on the device

Status: Accepted; full privacy verification pending.
Date: 2026-11-05.

## Context

Drawings and pet clips may contain identifying metadata. Loopback services
still need request isolation, and a public site should not collect uploads or
track visitors.

## Decision

I decode drawings into NumPy arrays and re-encode video so source EXIF and
container metadata do not enter outputs. Test committed images for EXIF and
videos for location tags.

I require the stdlib ThreadingHTTPServer to bind only 127.0.0.1 on a free port.
Generate a random token per launch, carry it in the opened URL, and require
X-Copypaw-Token for every /api/ request, including result files. Accept only
Host values 127.0.0.1:<port> and localhost:<port>. Limit raw request bodies to
60 MB and avoid a multipart parser. Store inputs and results in one OS-temp
session folder, remove it on exit, and remove stale copypaw-session-*
folders at the next launch. Log only method, path and status.

The site and /try/ load no analytics or third-party scripts and use self-hosted
fonts. Browser compute stays in the device. I will document verified behavior in
docs/privacy.md; tests/unit/test_app_server.py must enforce the local server
contract before release.

## Consequences

The project needs no upload service. Token and Host checks prevent unwanted
loopback access; process termination can leave temporary files until the next
launch. The separate consent-based field test uses the protocol in
docs/field_test.md, including its private intake and deletion schedule. That
research procedure is distinct from the product's local processing.

I have not established the full privacy contract with runtime evidence.
The initial verification records fixture and sample metadata checks only.
